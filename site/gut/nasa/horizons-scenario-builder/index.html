Horizons Scenario Builder

Public ephemeris-style scenario construction for deep-space optical-link and relativistic-correction studies.

Disclaimer — Horizons mode. Horizons mode uses public ephemeris data for public scenario construction. It does not call the live JPL Horizons API (CORS-restricted in static sites); instead it lets you paste Horizons output or load a cached public example. This is not a mission navigation pipeline and does not include mission-specific OD filters, covariance, tracking data, or internal operational products.

Send to calculator

Each button builds a URL with this scenario's numeric fields encoded as query parameters and navigates to the target calculator. Receiving calculators may inspect location.search via the scenarioFromUrl() helper.

Export

Download the constructed scenario as a JSON file. The file is self-contained: it embeds the scenario_id, the resolved numeric fields, the source citation, and a timestamp. Receiving calculators can ingest the same JSON in a later pass.

Why this exists

Public deep-space calculators are most useful when the geometry comes from a public source. JPL Horizons is the standard public ephemeris service. From a static-site browser, however, a direct fetch to ssd.jpl.nasa.gov/api/horizons.api is blocked by CORS — there is no Access-Control-Allow-Origin header on the response. This page therefore offers two reproducible alternatives:

  • Cached scenarios — a small JSON file of round-numbered public scenarios that load instantly with no network.
  • Paste mode — the user runs Horizons themselves (web UI or API) and pastes the result; the parser extracts range, range-rate, light-time, and (optionally) state vectors.

A future server-proxy mode is possible (the maintainer's GUT site already runs a Python deploy script). For Phase 1 the rule is simple: no live API call from the browser.

Source notes

  • Cached scenario provenance is annotated in cached_scenarios.json via the source_id field (cross-referenced to shared/source_registry.json).
  • Round numbers used in cached examples come from public press releases (NASA DSOC, Voyager mission status) or canonical textbook geometries (Will 2018 §6.4 for Mars solar conjunction).
  • Parsed Horizons output is treated as user-supplied data; the page records that it was parsed but does not vouch for the values.

What this would need for mission-grade use

Show requirements
  • Server-side proxy or signed-API integration with JPL Horizons (to bypass CORS without losing provenance).
  • SPICE kernel ingestion (BSP / SPK) rather than text scraping.
  • Full relativistic time-scale handling (TDB ↔ TT ↔ UTC).
  • Station coordinates + Earth orientation parameters.
  • Mission-specific OD filters, covariance, and tracking-data conditioning.
  • Versioned snapshot of the ephemeris used, with hash.
