The blind prediction method

Cosmology gives a structural theory one of its cleanest possible tests: a small set of precisely measured numbers describing the universe's expansion and its structure, produced by processes wholly independent of anything this program controls. The value of that test depends entirely on not looking at the answer before computing the guess. This page describes the discipline that enforces that, and reports the current status of the one pipeline built to use it: blocked.

Headline status: COSMOLOGY_COMPARISON = BLOCKED_PENDING_NATIVE_LAMBDA. The forward model that would turn a native cosmological constant into predicted expansion, distance, and structure-growth numbers is fully specified and built, but it has not run, because the native value of Λ it requires has not been computed. No observed cosmological data has been loaded. This is reported here exactly as it stands today — not softened, not implied to be further along than it is.

1. Orthogonal inputs, on purpose

The inputs that would go into this forward model — the candidate geometry's internal structure, its coupling constants, its vacuum-energy computation — come from a completely different line of work than the cosmological observations they would be checked against. The geometry was not built by looking at the measured expansion history, the cosmic microwave background power spectrum, or the observed dark-energy density, and it is not permitted to be adjusted using them. This separation — orthogonal inputs — is what makes a later agreement, if one is ever found, meaningful rather than circular.

Concretely, the observed quantities that this pipeline treats as strictly off-limits as derivation inputs, and usable only for an after-the-fact comparison once a native prediction exists, are:

Observed Λ / ρ_Λ

The measured cosmological constant or vacuum energy density.

H₀

The measured present-day expansion rate.

Ω_Λ / Ω_M

The measured dark-energy and matter density fractions.

Dark-energy / meV scale

The measured scale of the dark-energy density.

S₈

The measured amplitude of matter clustering.

BAO posterior

Measured baryon-acoustic-oscillation distances.

CMB posterior

Measured cosmic-microwave-background parameters.

2. How the forward model is meant to work

The pipeline (the cosmology forward-model pipeline) is a forward model: it takes native inputs only — a computed value for the effective cosmological constant, Λ_eff, and the native expansion ingredients that go with it — and produces predictions for a fixed list of observables:

QuantityWhat it is
H(z)the expansion history as a function of redshift
BAO distancescomoving and angular-diameter distances from baryon acoustic oscillations
SNe distance moduliμ(z), from the luminosity distance
CMB background consistencybackground-level checks such as θ*
Growth / S₈the linear growth of structure, if applicable
w₀ / wₐonly classifiable if the native residual evolves with time — see below

Each prediction, once made, would carry an uncertainty inherited honestly from the native input's own uncertainty ledger — not a post-hoc error bar picked to make agreement look better. Only after every native prediction is written down would the corresponding observed value be loaded, into a separate comparison table, for an after-the-fact residual.

3. Show the how — the sequencing rule

The rule that makes this a blind test rather than an exercise in curve-fitting is a strict ordering:

  1. Compute the native prediction first, using only the candidate geometry's own structure and previously-computed native inputs — never an observed cosmological number.
  2. Write the prediction down before any observed value is consulted, in a table that exists independently of the comparison.
  3. Only then load the observed value, into a separate table, and record the residual — agree or disagree — exactly as it comes out.

Running the steps out of order — loading an observed number before the native prediction is finished, or adjusting a native input after seeing a mismatch — is treated as a rule violation, not a shortcut. The pipeline has a built-in check for this and refuses to proceed if a native prediction has not been computed. As of today, that check is exactly why nothing has been loaded: the native prediction step has not been reached.

4. Agree or disagree — reported either way, per calculation

When the pipeline does run, each observable in the table above gets its own independent verdict — agreement or disagreement, at whatever precision the native uncertainty ledger supports. There is no single combined "the model works" or "the model fails" score. A structural theory that gets three cosmological observables right and one wrong is reported as three-right-one-wrong, not rounded to a pass or a fail. The completion report for this stage is explicit that if a native prediction misses an observation after the gate opens, that miss is reported as a genuine failure of that one calculation, not suppressed or explained away.

5. Never tune to match

A second discipline sits alongside the sequencing rule: even the qualitative structure of the model — for example, whether the vacuum-energy residual is treated as a true constant or as something that evolves with time — must be selected by the native geometry's own structure, never chosen after the fact because one branch fits the data better. The pipeline's documentation states this as a standing rule: the constant-versus-evolving branch is "selected by native structure, never by fit to data." This is the same anti-fitting discipline that governs every other gate on this site, applied here to cosmology specifically because cosmological data is exactly the kind of rich, multi-parameter dataset where after-the-fact tuning is easiest to smuggle in unnoticed.

6. The honest current status

BLOCKED_PENDING_NATIVE_LAMBDA

The forward model runs only if the upstream stage reports a computed native value for the effective cosmological constant. It currently reports the input as not yet computed. As a direct consequence:

  • The forward integration has not been run.
  • No observed cosmological data has been loaded — every entry in the comparison table reads NOT_LOADED.
  • Only a typed scaffold exists: prediction and comparison tables with the correct structure and units, and no numeric values.
  • Every row across both tables (H(z), BAO distance, SNe distance modulus, CMB background consistency, growth/S₈, w₀/wₐ) carries the status BLOCKED_PENDING_NATIVE_LAMBDA.

This is reported as a genuine blocker, not a rounding-down of a result that is "close enough" to done. Put plainly: the scaffold itself is sound and correctly typed, but a finished cosmology comparison is not yet in hand — that remains the intended, realistic outcome to work toward. The next step is to compute the native Λ_eff, then run the forward model, then load observed posteriors for the after-the-fact comparison — in that order, and not before.

7. Why report a blocked pipeline at all

Because the alternative — quietly waiting until the computation finishes and only then publishing a pipeline that "always" produced predictions — would hide the very discipline that makes the eventual result worth trusting. Showing the scaffold now, with its inputs pre-declared and its off-limits observational quantities pre-listed, is itself part of the falsifiability record: anyone can check, once Λ_eff is computed and the forward model runs, that no observed number was quietly folded in earlier than the rule allows.
