Test 6 — Gates × Foundational Constraints

The program is organized around a small set of Foundational Constraints and a checklist of specific structural requirements — "gates" — that any candidate shape must pass. This test is not a computation; it's a map. For each gate, which constraint is actually doing the work, and what is the gate's current honest status?

What was done

Eleven scoped requirements ("gates") were checked against the candidate shape — the compact internal geometry the program builds everything from. (These eleven are a specific scoped-GUT subset, not the full gate scoreboard — they are a worked slice, not a re-count of the site-wide gate roster.) Each gate names a frozen structural object it depends on, an output, a named failure mode a hostile reviewer could attack, and a status label drawn from a fixed, small vocabulary (never a vague word like "promising"). This table cross-references each gate against which Foundational Constraint is load-bearing for it — i.e., which constraint would have to be violated, or which frozen object removed, for that gate to fail.

Honest result

Ten of the eleven gates carry a claimed certificate pass or better under their declared assumptions; one (flavor closure, Gate 9) carries the qualified label certificate-complete under declared assumptions because it openly uses two calibration anchors rather than zero (see Test 2 for the full worked account, including its one disclosed weak row). No gate on this list is claimed to be a first-principles derivation from nothing; every "Claimed certificate pass" status is a claim about the internal consistency of the constructed geometry against a declared, falsifiable requirement — not a claim that the geometry itself is uniquely forced or proven correct. A companion falsification map (not reproduced in full here) names, gate by gate, exactly what a reviewer would need to show to force a downgrade — for example, an extra unobserved gauge factor for Gate 2, or a surviving vectorlike fermion pair for Gate 4.

Data sources

  • Gate definitions, statuses, and falsification map — the GUT manuscript's master gate-status table and per-gate falsification map (Gates 1–11), including the fixed status vocabulary (Claimed certificate pass, Certificate-complete under declared assumptions, Diagnostic only, Open / not claimed, Outside scoped-GUT claim).
  • Constraint definitions — see Foundational Constraints for the small set of consistency requirements each gate is checked against.

What this does not show

This table is a map of the program's own internal bookkeeping, not an independent audit by a third party. The status labels are self-reported by the same program that built the gates, using a fixed vocabulary specifically designed to prevent vague, inflated language — but a reader should treat "Claimed certificate pass" exactly as it is defined: a claim, with its verification path and failure mode named, not a peer-reviewed finding. See Gates for the fuller gate roster (including gates outside this scoped-GUT table) and their individual pages.
